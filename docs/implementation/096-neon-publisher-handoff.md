## Prepared behavior

`scripts/delivery/executor.mjs` supports a distinct `publishNeonDelivery` path. It checks external source/runtime/manifest pins and the packaging run-derived release name, then applies the existing conditional state lock, immutable inventory/receipts, ZIP publication, scoped CloudFormation change-set review, fixed-control publication and live acceptance. The first fixture-to-Neon transition requires an explicit boolean selection. An absent stack service role is permitted only for this reviewed fixture bootstrap; a foreign role or changed template is refused. Routine Neon updates retain the reviewed template. Recovery selects an existing retained version and restores its stored compatible frontend and runtime graph; it does not rebuild an old version or rotate a credential.

Runtime-aware acceptance is shared by publication, recovery and reconciliation. Neon requires matching-origin `platypus-neon-live-check` evidence. The CLI additionally verifies the exact runtime, storage/function origins, six check groups and fresh start/finish times. Reconciliation of an unassigned initial role requires both a fresh operator selection and bootstrap authorization in the immutable pending plan. It cannot add authorization to an ordinary pending operation.

`scripts/aws-live-check.mjs --runtime-variant neon` verifies the imported100000-ticket read-only dataset through bounded25/100-row pages, disjoint page2, a status filter, stable repeated access, directory counts100/40, malformed/unbounded refusal, sanitized legacy failure and no-store responses. The existing federation, private-path/S3/FunctionURL/CORS, three-route refresh/navigation, injected browser-only503/Retry and mobile checks remain. Browser paging/filter rows are compared with actual API pages. No idle waiting, database writes or secret retrieval is part of this checker. Cloud idle/wake behavior and actual SSM/Neon access still need learner live evidence.

`scripts/delivery/artifact-reader.mjs` adds a separate Neon selection path. It verifies exact repository and immutable owner/repository IDs, main, successful manual `.github/workflows/package-neon.yml` attempt, matching source, official artifact ID/name/size/digest and timestamps, bounded ZIP structure and external manifest/runtime pins. API credentials are never forwarded to redirected artifact storage. Extraction uses a new owned scratch workspace. The legacy Package reader retains its old workflow/envelope contract. Neither reader starts a workflow.

`scripts/delivery/cli.mjs publish-neon` requires `--target`, `--selection`, `--runtime`, and optionally `--allow-neon-transition true|false`. It authenticates and downloads the selected GitHub package before any AWS write. The GitHub credential comes only from `PLATYPUS_GITHUB_READ_TOKEN`, never a command argument or tracked file. Import and reconciliation accept the explicit bootstrap option; ordinary fixture publication and recovery do not acquire that option. Configuration files must be bounded ordinary JSON files.

`buildAccessDocuments({neonBackend:true})` adds read/inline-policy management on only the existing Lambda execution role. This matches the manually prepared CFN role permissions. IAM PutRolePolicy can write arbitrary inline policy content on that one role: the exact secret policy is enforced by template/change-set review, not an IAM condition constraining JSON content. The default legacy generator retains its prior permissions. `buildCodeBuildAccessDocuments` adds CodeBuild trust bound to the exact account/project, the existing publisher envelope, exact publisher logs, and `ssm:GetParameters` on only `/platypus-service/delivery/github-read-token`. It grants no direct Lambda code/alias mutation or Neon-password read to the CodeBuild publisher. These functions only return documents; no policy is installed.

## CodeBuild configuration prepared for review

Use project `platypus-service-publisher`, eu-north-1, No source, no artifacts, one build at a time, zero automatic retries, no webhook or scheduled trigger, no VPC/privileged mode/fleet. Use managed Ubuntu24.04 `aws/codebuild/standard:8.0`, small compute, CloudWatch logs and a bounded build timeout. This replaces the earlier provisional Amazon Linux image because the prepared browser dependency installation targets Ubuntu. Actual image availability, installation and Free-account permissions must be checked during learner setup; no CodeBuild container has been exercised here.

Copy the complete contents of `infrastructure/buildspec-neon-publisher.yml` into the project's inline buildspec. No-source projects require inline buildspec contents, not a repository filename. It fetches the fixed public repository's main branch, requires its commit to equal the externally reviewed `PLATYPUS_PUBLISHER_SHA`, installs pinned Node24.21.0/npm11.19.0 and locked dependencies, installs the Playwright Chromium used by the pinned dependency, then calls the reviewed adapter. It does not build an application candidate or invoke Package. The adapter refuses another CodeBuild account/project, a local profile, changed publisher source, mismatched runtime/target/origin, unknown configuration fields and missing explicit transition/confirmation inputs.

Environment inputs are nonsecret except the dedicated artifact-read credential:

| Name                             | Source and meaning                                                                                                   |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `PLATYPUS_PUBLISHER_SHA`         | Exact reviewed main commit containing this publisher                                                                 |
| `PLATYPUS_TARGET_JSON`           | Compact delivery-target JSON; exact reviewed IDs, no profile or extra fields                                         |
| `PLATYPUS_SELECTION_JSON`        | Externally reviewed selection from `neon-artifact-selection.example.json`; all placeholders replaced                 |
| `PLATYPUS_RUNTIME_JSON`          | Reviewed nonsecret runtime JSON with exact existing password-parameter version                                       |
| `PLATYPUS_ALLOW_NEON_TRANSITION` | Explicit `true` for the reviewed first transition; `false` for routine Neon updates                                  |
| `PLATYPUS_CONFIRM`               | Keep `disabled` until the learner intentionally starts the reviewed publication; the adapter requires `publish-neon` |
| `PLATYPUS_GITHUB_READ_TOKEN`     | Parameter Store mapping in the buildspec, never plaintext project/build input                                        |

The distinct `/platypus-service/delivery/github-read-token` must be an operator-created Standard SecureString containing a GitHub read credential restricted to this repository and Actions-read/necessary metadata access. It is not the Neon password and has not been created or read by the coordinator. Review expiry and current authorization before setup. Source checkout is public HTTPS with no source PAT or federation provider. A separate authenticated GitHub API read is still required for the selected artifact. Preserve Free plan; no advanced activation or new paid service is implied.

For an exact reviewed selection, access documents can be generated locally by importing `buildCodeBuildAccessDocuments` with the target, `lambdaExecutionRoleArn`, fixed project name and GitHub `{repository,repositoryId,ownerId,environment:'aws-learning',ref:'refs/heads/main'}`; map `ownerId` from the reviewed selection's `repositoryOwnerId`. Review and apply publisher documents only to the CodeBuild role, and service documents only to the CFN role. Do not attach either to the Lambda runtime role.
