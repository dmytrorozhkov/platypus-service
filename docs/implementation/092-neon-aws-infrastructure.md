## Implemented interfaces

- `scripts/neon-aws/templates.mjs` exports `neonBackendTemplate()`, `validateNeonRuntimeConfig(config)`, `computeNeonBackendRevision(config, codeSha256)` and `neonBackendParameters(config, packageInputs)`.
- The validator returns a fresh, canonical exact-key schema1 `platypus-neon-runtime` object. It requires eu-north-1, a nonzero twelve-digit account ID, an exact HTTPS CloudFront origin, a Frankfurt pooled hostname, neondb/platypus_app, the same-account exact production password parameter ARN and a positive safe-integer version. Extra/credential/profile/endpoint fields, accessors, inherited shapes, URLs, wrong regions and placeholder accounts fail with fixed nonsecret errors. Validation does not prove live ownership, permission or existence.
- The revision is SHA256 of the existing canonical two-space JSON/newline serialization of `{kind:'platypus-neon-backend-revision',packageSha256:codeSha256,runtime:validatedConfig}`. The ZIP hash is canonical SHA256 base64. Every runtime value, including parameter version, is part of the revision. The helper returns a plain CloudFormation parameter map from config plus `{bucket,key,sha256,concurrencyMode?,rollbackVersion?}`. Only the already accepted account-cap-ten mode is permitted; rollback version is empty or an explicit positive version.
- `infrastructure/neon-backend.template.json` is the exact generated derivative, not a replacement for `infrastructure/backend.template.json`. The original fixture generator and template are unchanged.
- `infrastructure/neon-runtime.example.json` contains only nonsecret references. Its zero account ID deliberately fails preparation until an exact current target/parameter/version is supplied and verified. Example host/origin reflect learner-provided prior evidence, not a fresh account read. The example's version1 is illustrative, not an observed SSM version.

## Template behavior and preservation

The additive generator starts from a fresh existing `backendTemplate()` result. It keeps all six logical IDs (Logs, ExecutionRole, Function, Version, LiveAlias, FunctionUrl), outputs, conditions, Lambda architecture/runtime/handler identity, code source, CloudFront-signed AWS_IAM Function URL, exact origin protection, seven-day owned log group, existing log policy, retained versions and stack-managed alias rollback. It creates no parallel function, VPC/NAT, database, secret resource or customer-managed key. Preserve the existing backend stack identity when the learner later publishes.

Lambda timeout becomes30seconds; all new environment values are nonsecret references. Variables are ALLOWED_ORIGINS, NEON_HOST, NEON_DATABASE, NEON_USER, NEON_CONFIRM_TARGET, NEON_PASSWORD_PARAMETER_ARN and NEON_PASSWORD_PARAMETER_VERSION. AWS_REGION remains Lambda-provided; NEON_PASSWORD and secret dynamic references are absent. Parameter defaults do not invent a concurrency/origin/target decision. Existing UseReservedTwo condition is retained for identity/context compatibility, while the opt-in candidate permits only accepted cap-ten.

The role gains exactly one named action, ssm:GetParameter, scoped to `arn:${AWS::Partition}:ssm:eu-north-1:${AWS::AccountId}:parameter/platypus-service/production/neon/password`. The resource has no wildcard and cannot grant another account's parameter. No list/history/path retrieval/write action or direct KMS permission is added. Both environment ARN and policy resource derive from the same actual account/fixed Region/path intrinsic; NEON_CONFIRM_TARGET derives from NeonHost plus `/neondb`. The redundant ARN/confirmation CloudFormation parameters were removed with root approval so a direct parameter invocation cannot introduce cross-field mismatches. Runtime config still independently pins the ARN/account and confirmed host into the revision; root publication must verify the actual target, and the Lambda adapter must verify its invoked-function account and Region before I/O. This source preparation does not substitute for actual target/role/SCP verification.

IAM input-gate decision: contract090 explicitly supplies the single GetParameter operation and exact resource path. This is the skill's named-operation Service Authorization Reference path, not policy inference from application SDK source or Terraform. The public programmatic service authorization JSON was read successfully and maps GetParameter to parameter resources with ARN format `arn:${Partition}:ssm:${Region}:${Account}:parameter/${ParameterNameWithoutLeadingSlash}`. IAM is scoped to the parameter resource, not an invented version-specific ARN; the runtime request/response verification pins the immutable version. No policy tool or global software was installed.

CloudFormation context and the idempotent aws-cloudformation@3 attribution are preserved/extended. New significant decisions use resource-level why/must metadata. Template size before derivation was9,930bytes and the final candidate12,977bytes (both below51,200 inline and1,048,576 S3 limits); six resources remain.
