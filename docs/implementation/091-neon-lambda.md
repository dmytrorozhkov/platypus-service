## Runtime interface and ownership

`neon-lambda.ts` exports `createNeonLambdaHandler` and the default `handler`. Factory construction snapshots the supplied environment and performs no SDK client creation, secret load, pool creation, SQL, listener or process-hook operation. The factory accepts synthetic `getPassword({environment,accountId,signal})` and synchronous `createConnection({environment,operationTimeoutMillis,closeTimeoutMillis})` boundaries; the callable handler also exposes an idempotent owned-resource `close()` test seam.

It reuses `createLambdaHandler`, existing request/CORS/query validation, `PostgresTicketRepository`, strict `readNeonRuntimeConfiguration`, `probeNeonConnection` and `createNeonConnection`. Health, preflight, unsupported/invalid requests, disallowed browser origins and invalid ticket queries do not initialize secrets/SQL. The legacy collection route refuses without reading data; only bounded paged reads and directory options use Neon. No fixture fallback is possible. Cloud origins are explicitly one exact HTTPS CloudFront origin.

Business requests require a trusted Lambda context ARN in `eu-north-1`, with the same account as the exact SSM parameter ARN, plus a valid remaining-time value. The handler disables waiting for empty event-loop handles, allowing the successfully initialized connection to remain warm without keepalive/polling queries. Cold initialization is serialized: load one pinned secret, validate the restricted target, create one max2 pool through the reviewed adapter and complete the effective-role/read-only probe before business SQL. Warm requests reuse that connection. A failed invocation is never replayed; later explicit invocations may initialize again after owned cleanup. Failed cleanup poisons the environment rather than opening overlapping replacement pools.

The adapter operation budget is shortened to8seconds; overall request budget is at most25seconds or remaining Lambda time minus a fixed4second cleanup margin. SSM is bounded to3seconds and connection cleanup to3seconds. Test seams may shorten, never enlarge, these limits. Request expiry retires initialization/current connection, aborts secret work, rejects the request and prevents late business work/cache resurrection. Late promise settlements are observed. Shutdown has no process or HTTP listener and closes only this factory's resources.

## Runtime-pinned SSM secret

`neon-secret.ts` exports `readNeonSecretConfiguration` and `loadNeonPassword`. It requires `AWS_REGION=eu-north-1`, no ambient `NEON_PASSWORD`, the exact same-account ARN for `/platypus-service/production/neon/password`, and a canonical positive safe-integer `NEON_PASSWORD_PARAMETER_VERSION`. The ARN/version are release inputs; no latest-value or stale-password fallback exists.

The SDK v3 reader uses root imports `SSMClient`/`GetParameterCommand`, explicit region, `maxAttempts:1`, disabled configured endpoint-URL overrides, bounded transport and an owned AbortController with parent cancellation. It requests `Name=ARN:version` and `WithDecryption=true`. The response must have Type SecureString and exact ARN/name/version; any present selector must match. Its value must satisfy the existing app password's20–128 printable ASCII contract. The owned SDK transport is destroyed after success/failure/cancellation. No SDK/driver error, response, password/hash, host or private cause is logged or returned in diagnostics. The client is created only inside a real load call, never at import.

Parameter creation, Standard tier/AWS-managed key selection, effective IAM/KMS permission, Free-account eligibility and cost verification are separate learner prerequisites. Source preparation does not provision a parameter or promise universal free access. Pinned versions make release/rollback inputs explicit, but database credential compatibility remains necessary when rotating or rolling back.
